std.strbuf

std.strbuf — the one string builder (D24). Stability tier: core.

What is the language's and what is std's. Nothing here is the language's yet: str is the language's immutable UTF-8 slice, and D24 promises strbuf as an owned, growable, SSO-backed builder that auto-borrows to str — compiler-side plumbing (s37 §3) that does not exist at this pin. This module is the API surface that plumbing will back, written today over the one thing that does exist: a str field rebuilt by interpolation.

THE BACKING IS AN INTERIM, and it is a performance interim, not a semantic one. push_str allocates a fresh str and copies both sides, so appending n times over a buffer of length m is O(n·m) where the SSO builder is amortized O(n+m). Every function's meaning is final; the complexity notes say "the SSO backing will make this O(1) amortized" wherever that is the only difference. No caller has to change when the backing lands (F-0019), and this file is where the layout note for s41/s43's ABI document will hang.

StrBuf is CapCase per API-CONVENTIONS §1 even though the sprint contract writes the constructor as strbuf(): a callable type name is s37's builtin spelling, and strbuf.new() is the module spelling available today. That delta is recorded in the campaign closeout.

insertfnpub

fn insert(mut b: self.StrBuf, off: int, s: str) · regions (ρ1, -, -) -> -

Inserts s at byte offset off, shifting everything at or after off to the right. off == len(b) appends; off == 0 prepends.

Traps bounds ([conf.trap.set]) when off is out of range or falls inside a code point — the language's own checked slicing (D25), raised exactly where a caller would see it. That is the "checked boundary" the contract asks for; the recoverable form — an insert that raises rather than traps — is writable over str.get as of s37 (sc09) and is a std.strbuf sprint's to add, under its own name, beside this one.

strbuf.insert(mut b, 0, "the ")
strbuf.to_str(b) == "the wolf"

pushfnpub

fn push(mut b: self.StrBuf, c: char) · regions (ρ1, -) -> -

Appends one code point — the sc03 contract's push(c), code at last (sc24), over D58's char ([type.char]: a Unicode scalar value, ordered, NOT an integer). The body is b.s += c, which [type.str.concat] rules to append THE CHARACTER — so the appended bytes are exactly c's UTF-8 encoding, 1 to 4 of them, and the buffer's UTF-8 validity is preserved by construction: no int ever touches this path, and a non-scalar cannot exist as a char at all (the D56 cast already trapped it). O(len(b)) with the interim backing, amortized O(1) once the SSO builder lands. Total: no error row, no traps beyond allocation.

It was an interpolation hole until sc43 — b.s = "{b.s}{c}" — and the hole existed for exactly one reason: + refused a char, so the only way to put one on the end of a str was to render it into a new string. wolf-lang#278 admitted a char on either side of + and as the value of += at v0.2.9, and lupin 0.1.31 mirrored it (is43, wolf-interp#78). The two appenders are written in one idiom now — this line and push_str's are the same line with a different operand type — and [type.char.interp] is no longer what carries the character across; [type.str.concat] is.

LANES: every executing lane runs this as of the sc25 pins — both wolf rungs since s121, lupin since 0.1.15 (is26, the scalar release; sc24's one-sprint unsupported there closed on it). The example keeps its "é🐺".chars() spelling because the walk is the natural producer here, not as the lex-dodge it was under 0.1.14.

doctestwolf-doc-example example, run by its own rig

var b = strbuf.new()
for c in "é🐺".chars() { strbuf.push(mut b, c) }
strbuf.to_str(b) == "é🐺"
strbuf.len(b) == 6

push_strfnpub

fn push_str(mut b: self.StrBuf, s: str) · regions (ρ1, -) -> -

Appends s to the end of the buffer. O(len(b) + len(s)) with the interim backing, amortized O(len(s)) once the SSO builder lands. Total: no error row, no traps beyond allocation.

The += spelling the sprint contract mentions — b += s on the BUFFER — is not available: the operator-to-method bridge is F-0004's open question, and wolf has no operator overloading, so a StrBuf cannot be the left side of one. push_str is the one spelling std writes. (The sentence that stood here until sc43 went on to say + on str "runs in lupin and is E0409 in wolfc". That was true when it was written and stopped being true at D62, which this very body adopted: b.s += s is a str += on all three lanes, and sc43's push is now its char twin one function down.)

removefnpub

fn remove(mut b: self.StrBuf, from: int, to: int) · regions (ρ1, -, -) -> -

Removes the bytes in [from, to), closing the gap. Empty when from == to.

Traps bounds when the range is out of order, out of range, or splits a code point (D25, as insert). The contract writes this as remove(a..b); a range is not a value that can cross a function boundary at this pin (fn f(r: Range) is E0301 in wolfc), so the two offsets are spelled as two parameters — the same interim str.get carries, flipping together with it.

var b = strbuf.new()

truncatefnpub

fn truncate(mut b: self.StrBuf, n: int) · regions (ρ1, -) -> -

Shortens the buffer to n bytes, dropping everything after. Keeps the buffer usable and is a no-op when n == len(b).

Traps bounds when n exceeds the length or splits a code point (D25) — truncation is exactly a checked slice.
